# I-NNOVA KICKSTARTER — Data Science Track
## Milestone 2: Python Fundamentals for Data

**Status:** Draft for review
**Unlocks:** After Milestone 1 is fully completed
**Theme:** Python from zero — variables, control flow, functions, and core data structures — taught with data-flavored examples throughout so fellows immediately see *why* each concept matters, rather than generic exercises.
**Target fellow:** Has a working Colab/Kaggle setup and has explored Nkwen Traders' Chapter 1 data; zero prior programming experience assumed.

---

### Activity 2.1 — Variables, Data Types & Basic Operations
- **Type:** `learning`
- **Pillar:** Build
- **Difficulty:** Beginner
- **Base Points:** 10
- **Deadline:** 3 days | **Grace Period:** 1 day | **Late Penalty:** 10%
- **Chain Parent:** None | **Prerequisites:** Activity 1.4
- **Evidence Required:** URL/Link (Kaggle/Colab notebook)
- **Prompt:** Learn variables, core types (int, float, str, bool), and basic arithmetic/string operations. Fellow writes a notebook that stores a few facts about one Nkwen Traders product (name, price, quantity in stock) as variables, then computes and prints the total value of that stock (price × quantity) with a formatted sentence output.
- **Rubric:**
  1. *Correctness* (60%) — Are variables and the calculation correct?
  2. *Output Quality* (40%) — Is the printed output well-formatted and readable (not just raw numbers)?

### Activity 2.2 — Control Flow: Conditionals
- **Type:** `learning`
- **Pillar:** Build
- **Difficulty:** Beginner
- **Base Points:** 10
- **Deadline:** 3 days | **Grace Period:** 1 day | **Late Penalty:** 10%
- **Chain Parent:** Activity 2.1 | **Prerequisites:** Activity 2.1
- **Evidence Required:** URL/Link (Kaggle/Colab notebook)
- **Prompt:** Learn `if`/`elif`/`else` and comparison/logical operators. Fellow writes a function that takes a stock quantity and returns a status label — "Out of Stock" (0), "Low Stock" (1–10), "Well Stocked" (11+) — and tests it against 5 different sample quantities.

### Activity 2.3 — Lists & Loops
- **Type:** `learning`
- **Pillar:** Build
- **Difficulty:** Beginner
- **Base Points:** 15
- **Deadline:** 3 days | **Grace Period:** 1 day | **Late Penalty:** 10%
- **Chain Parent:** Activity 2.2 | **Prerequisites:** Activity 2.2

### Activity 2.5 — Functions & Reusable Logic
- **Type:** `learning`
- **Pillar:** Build
- **Difficulty:** Beginner
- **Base Points:** 15
- **Deadline:** 3 days | **Grace Period:** 1 day | **Late Penalty:** 10%
- **Chain Parent:** Activity 2.4 | **Prerequisites:** Activity 2.4
- **Evidence Required:** URL/Link (Kaggle/Colab notebook)
- **Prompt:** Learn how to write functions with parameters, default values, and return values, and *why* functions matter for avoiding repetition (foreshadowing writing reusable analysis code later). Fellow refactors their work from Activities 2.2 and 2.4 into clean, reusable functions (e.g., `classify_stock(quantity)`, `calculate_inventory_value(products)`), and calls them on new sample data to prove they generalize beyond the original examples.
- **Rubric:**
  1. *Correct Refactoring* (50%) — Are the functions correctly extracted and still produce correct results?
  2. *Generalization* (30%) — Do the functions work correctly on genuinely new data, not just the original example?
  3. *Code Quality* (20%) — Sensible parameter names, docstrings/comments?

### Activity 2.6 — Problem Solving 102: Debugging Practice
- **Type:** `learning`
- **Pillar:** Build
- **Difficulty:** Intermediate
- **Base Points:** 15
- **Deadline:** 3 days | **Grace Period:** 1 day | **Late Penalty:** 15%
- **Chain Parent:** None | **Prerequisites:** Activity 2.5
- **Evidence Required:** Written Submission + URL/Link (fixed notebook)
- **Prompt:** Fellow is given 4–5 short, deliberately broken Python snippets (a classic off-by-one loop error, a `TypeError` from mixing str/int, an incorrectly indented block, a logic error that runs but gives wrong output). Fellow identifies and fixes each, writing a short note on what was wrong and how they found it (reading the error message, using `print()` to trace values — the actual habits of real debugging).
- **Rubric:**
  1. *Correct Fixes* (60%) — Are all bugs correctly identified and fixed?
  2. *Debugging Process* (40%) — Is the explanation of *how* they diagnosed each bug genuine and sound?

### Activity 2.7 — Project: Nkwen Traders Sales Calculator
- **Type:** `project`
- **Pillar:** Build
- **Difficulty:** Intermediate
- **Base Points:** 20
- **Deadline:** 4 days | **Grace Period:** 2 days | **Late Penalty:** 15%
- **Chain Parent:** Activity 2.5 | **Prerequisites:** Activity 2.5, Activity 2.6
- **Evidence Required:** URL/Link (public Kaggle notebook)
- **Prompt:** Bring together everything from this Milestone: given a hardcoded list of dictionaries representing a week of Nkwen Traders sales transactions (product, quantity sold, price), write a small program (pure Python, no pandas yet) that reports: total revenue for the week, best-selling product by quantity, and a day-by-day breakdown — all via well-structured functions, not one giant script.
