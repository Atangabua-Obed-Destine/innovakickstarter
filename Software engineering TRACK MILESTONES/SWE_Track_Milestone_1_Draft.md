# I-NNOVA KICKSTARTER — Software Engineering Track
## Milestone 1: Welcome to Software Engineering

**Status:** Draft for review
**Unlocks:** Immediately upon enrollment
**Theme:** Orientation, programming fundamentals, problem-solving mindset, first real commits.
**Target fellow:** Zero prior coding experience welcome. This Milestone is the on-ramp for people transitioning in from other fields.

> **Open question for Kento:** Points below are illustrative (kept low/modest per activity). Since the tier scale is fixed at 0–100 total, we need to decide whether Career Capital is normalized against total track points, calculated as a percentage, or something else — otherwise fellows will blow past "Elite" within the first Milestone or two. Flagging before we lock in numbers across the whole track.

### Activity 1.1 — What Is a Software Engineer, Really?
- **Type:** `learning`
- **Pillar:** Build (foundational orientation)
- **Difficulty:** Beginner
- **Base Points:** 5
- **Deadline:** 2 days | **Grace Period:** 1 day | **Late Penalty:** 10%
- **Chain Parent:** None | **Prerequisites:** None
- **Evidence Required:** Text Response
- **Resources:** https://www.youtube.com/watch?v=1LSXEC0Clow, https://www.coursera.org/articles/software-engineer
- **Prompt:** Fellow reads/watches a short curated overview of what software engineers actually do day-to-day (not just "coding") — problem-solving, collaboration, debugging, communicating with non-technical people — then writes a short reflection on which part excites them most and why they want to learn this.
- **Rubric:**
  1. *Understanding* (60%) — Does the reflection show genuine grasp of what the role involves beyond "writing code"?
  2. *Personal Motivation* (40%) — Is there a clear, honest reason for pursuing this path?

### Activity 1.3 — Programming Logic: Variables, Data Types & Control Flow
- **Type:** `learning`
- **Pillar:** Build
- **Difficulty:** Beginner
- **Base Points:** 10
- **Deadline:** 3 days | **Grace Period:** 1 day | **Late Penalty:** 10%
- **Prerequisites:** Activity 1.2
- **Evidence Required:** Text Response
- **Resources:** https://www.youtube.com/watch?v=jS4aFq5-91M, https://www.w3schools.com/js/js_control_flow.asp
- **Prompt:** Language-agnostic first — fellow works through variables, data types, conditionals, and loops using plain pseudocode/flowcharts (no syntax yet). Ends with 3–5 short "predict the output" style logic exercises answered in writing.
  > *Recommended Resource:* The early sections of freeCodeCamp's **JavaScript Algorithms and Data Structures** certification are perfect for grasping these core concepts.
- **Rubric:**
  1. *Conceptual Accuracy* (70%) — Are the logic exercises answered correctly?
  2. *Clarity of Reasoning* (30%) — Can the fellow explain *why*, not just guess the answer?

### Activity 1.4 — Problem Solving 101: Breaking Down a Problem
- **Type:** `learning`
- **Pillar:** Build
- **Difficulty:** Beginner
- **Base Points:** 10
- **Deadline:** 3 days | **Grace Period:** 1 day | **Late Penalty:** 10%
- **Chain Parent:** Activity 1.3 | **Prerequisites:** Activity 1.3
- **Evidence Required:** Text Response
- **Resources:** https://www.youtube.com/watch?v=7UlslIXHNsw, https://www.freecodecamp.org/news/problem-solving-and-technical-interview-prep/
- **Prompt:** Introduce a simple problem-decomposition framework (understand → plan → break into steps → solve → review). Fellow applies it to 2–3 everyday, non-code problems (e.g., "how would you organize a queue at a supermarket checkout?") and one very simple logic puzzle, writing out their step-by-step thinking.
- **Rubric:**
  1. *Decomposition Skill* (60%) — Did they break the problem into clear, logical steps rather than jumping to a guess?
  2. *Communication* (40%) — Is the written reasoning easy for a reviewer to follow?

### Activity 1.5 — Intro to Git & GitHub
- **Type:** `project`
- **Pillar:** Build
- **Difficulty:** Beginner
- **Base Points:** 10
- **Deadline:** 3 days | **Grace Period:** 2 days | **Late Penalty:** 15%
- **Chain Parent:** None | **Prerequisites:** Activity 1.2
- **Evidence Required:** URL/Link (GitHub repo)
- **Resources:** https://www.youtube.com/watch?v=mAFoROnOfHs, https://www.freecodecamp.org/news/learn-how-to-use-git-and-github-a-beginner-friendly-handbook/

  2. *Commit Quality* (60%) — Are there at least 3 distinct, meaningfully-messaged commits (not just "update")?

### Activity 1.6 — Build Your First Program: FizzBuzz
- **Type:** `project`
- **Pillar:** Build
- **Difficulty:** Beginner
- **Base Points:** 15
- **Deadline:** 3 days | **Grace Period:** 1 day | **Late Penalty:** 15%
- **Chain Parent:** Activity 1.5 | **Prerequisites:** Activity 1.3, Activity 1.5
- **Evidence Required:** URL/Link (GitHub repo/gist)
- **Resources:** https://www.youtube.com/watch?v=jS4aFq5-91M, https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/for
- **Language:** JavaScript (chosen as the entry language since it transfers cleanly to both frontend and backend work later in the track)
- **Prompt:** Classic FizzBuzz — print numbers 1–100, but "Fizz" for multiples of 3, "Buzz" for multiples of 5, "FizzBuzz" for both. Push the code to the GitHub repo from Activity 1.5.
  > *Recommended Resource:* If you get stuck, freeCodeCamp's **Basic JavaScript** module covers all the syntax (loops and if-statements) needed to solve this.
- **Rubric:**
  1. *Correctness* (70%) — Does the program produce the correct output for all cases?
  2. *Code Readability* (30%) — Is it reasonably clean (sensible variable names, no unnecessary repetition)?
