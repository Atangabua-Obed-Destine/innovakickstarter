# How we work on this repository

1. **Never commit straight to `main`.** `main` is protected: changes arrive only through pull requests.
2. **One branch per feature**, named `feature/<short-name>`, for example `feature/branch-finder`.
3. **Small commits with clear messages** in the present tense: "Add branch list page", not "update".
4. **Run `node --test` before you push.**
5. **Open a pull request** and fill in every part of the template.
6. **Review kindly and specifically.** Say what you see, why it matters, and suggest a fix or ask a question.
   Mark small style points as "nit:". Praise what is good.
7. **The author answers every comment**, with a new commit or a reply, before merging.
8. **Merge only after one approval.** Delete the branch after merging.
